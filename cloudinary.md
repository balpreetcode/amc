# Cloudinary Video Library Integration

## Overview

This document describes the Cloudinary Video Library feature that allows users to store, manage, and playback videos generated from workflows. Videos are automatically uploaded to Cloudinary and can be accessed through the "Videos" page in the application.

---

## Features

### 1. Video Library Page (6th Tab)

**Location**: `/videos` route in the frontend

**Features**:
- Display all videos uploaded to Cloudinary
- Video cards with thumbnails, metadata, and action buttons
- Play videos in a modal player
- Download videos directly
- Delete videos from Cloudinary
- Responsive grid layout
- Real-time video count

**Video Card Information**:
- Video thumbnail (first frame from Cloudinary)
- Video filename
- Upload timestamp (relative: "Just now", "5m ago", "2h ago", "Jan 8")
- File size
- Duration badge
- Play, Download, Delete buttons

---

## Architecture

### Cloudinary as Source of Truth

The implementation uses **Cloudinary as the primary storage** for videos. There is no database table for video metadata - all information is fetched directly from Cloudinary's API.

**Why this approach?**
- Simpler architecture (no database sync issues)
- Cloudinary handles video storage, transcoding, and CDN delivery
- Built-in thumbnail generation
- Direct video URL generation
- No additional infrastructure needed

**Trade-offs**:
- Cannot store custom metadata easily (would require database)
- Dependent on Cloudinary API availability
- Limited to Cloudinary's retention policy

## Node 10 Integration Plan

### Overview

Node 10 is the final video generation node in the workflow (typically `edit_video` or `clip_merger`). After this node completes, the generated video should be automatically uploaded to Cloudinary.

### Integration Steps

#### 1. Identify Node 10

**File**: `backend/generators/edit_video.js` or `backend/generators/ffmpeg.js`

Node 10 is typically the video composition/merge operation that produces the final video output saved to `/output/` directory.

#### 2. Add Cloudinary Upload Call

**Location**: After video file is saved locally

**Current Flow** (approximate):
```
Node 10 executes → Generates video → Saves to /output/final_video.mp4 → Returns result
```

**New Flow**:
```
Node 10 executes → Generates video → Saves to /output/final_video.mp4 → Uploads to Cloudinary → Returns result with Cloudinary URL
```

#### 3. Implementation Code Addition

**Add to Node 10 Generator**:

```javascript
// After local file save
const { uploadVideo } = require('../services/cloudinary');

// Upload to Cloudinary
const uploadResult = await uploadVideo(outputPath, {
  originalFilename: filename
});

// Include Cloudinary info in response
return {
  ...existingResult,
  cloudinaryUrl: uploadResult.cloudinaryUrl,
  cloudinaryPublicId: uploadResult.publicId
};
```

#### 4. Update Node Execution Response

**File**: `backend/server.js` in the node processing section

**Current Response Structure**:
```javascript
{
  nodeId: "node_10",
  status: "success",
  data: {
    videoUrl: "/output/final_video.mp4"
  }
}
```

**Enhanced Response** (after Cloudinary integration):
```javascript
{
  nodeId: "node_10",
  status: "success",
  data: {
    videoUrl: "/output/final_video.mp4",
    cloudinaryUrl: "https://res.cloudinary.com/...",
    cloudinaryPublicId: "workflow_videos/abc123",
    uploadedToCloudinary: true
  }
}
```

#### 5. Error Handling Strategy

**If Cloudinary Upload Fails**:
- Log the error to console
- Continue workflow execution (don't fail the workflow)
- Return local video URL as fallback
- Include error information in workflow execution history

**Rationale**: A workflow should not fail entirely just because Cloudinary upload fails. The local video is still available.

## Cloudinary Configuration Details

### Folder Structure

**Folder**: `workflow_videos/`

**Public ID Pattern**: `workflow_videos/{unique_id}`

**Example**: `workflow_videos/uzxrcng4gzt4ptu1lmj5`

### Thumbnail Generation

Cloudinary automatically generates JPG thumbnails from uploaded videos at the first frame.

**URL Pattern**:
- Original video: `https://res.cloudinary.com/.../upload/video.mp4`
- Thumbnail: `https://res.cloudinary.com/.../upload/video.jpg`

**Manual Transformations** (can be applied):
- Width/Height: `w_400,h_225,c_fill`
- Format: `jpg`
- Quality: `q_80`

## Video Deletion

### Process

1. User clicks "Delete" button on video card
2. Confirmation modal appears
3. Frontend calls `DELETE /api/videos/:publicId`
4. Backend calls `cloudinary.uploader.destroy(publicId)`
5. Cloudinary deletes video and all derived resources
6. Database (if any) updated to `status='deleted'`
7. Frontend removes video from list

**What Gets Deleted**:
- Original video file
- All derived/transformed versions
- Thumbnails

**Irreversible**: Deletion is permanent and cannot be undone.

## Troubleshooting

### Issue: Videos Not Showing

**Symptoms**: Empty state or raw JSON display

**Causes**:
1. Backend not running on port 3002
2. Cloudinary credentials invalid
3. No videos uploaded yet
4. Frontend needs restart (proxy changes)

**Solutions**:
1. Check backend logs: `node server.js`
2. Verify Cloudinary credentials in `.env`
3. Upload a test video via script
4. Hard refresh browser: `Ctrl+Shift+R`

### Issue: Thumbnails Not Loading

**Symptoms**: Generic placeholder icon instead of video thumbnails

**Causes**:
1. Cloudinary URL format incorrect
2. Video not fully processed on Cloudinary
3. Cloudinary auto-thumbnail not generated

**Solutions**:
1. Verify video exists in Cloudinary dashboard
2. Wait a few seconds for Cloudinary processing
3. Check URL ends with `.jpg` not `.mp4`

### Issue: Upload Fails

**Symptoms**: Error message during upload

**Causes**:
1. Invalid Cloudinary credentials
2. File not found in output folder
3. File too large for Cloudinary free tier
4. Network issues

**Solutions**:
1. Verify `.env` credentials
2. Check file exists in `backend/output/`
3. Try smaller video file
4. Check internet connection

## API Reference

### GET /api/videos

List all videos from Cloudinary.

**Query Parameters** (optional):
- `page` (number): Page number (default: 1)
- `pageSize` (number): Items per page (default: 50)
- `status` (string): Filter by status

**Response**: VideosListResponse

### DELETE /api/videos/:publicId

Delete a video from Cloudinary.

**Parameters**:
- `publicId` (path): Cloudinary public ID

**Response**:
```json
{
  "success": true,
  "message": "Video deleted successfully"
}
```

### POST /api/videos/upload

Upload a video file to Cloudinary (testing endpoint).

**Body**:
```json
{
  "filename": "video.mp4"
}
```

**Response**: UploadedVideo object

1. **Public ID Validation**: Prevent directory traversal attacks
2. **File Size Limits**: Cloudinary has limits per plan tier
3. **Rate Limiting**: Consider rate limiting for uploads
4. **Access Control**: Videos are publicly accessible via URL
5. **Input Validation**: Validate all filenames and parameters
